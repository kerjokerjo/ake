## 任务 B3：搭建"竞赛登记管理系统"工程骨架（支撑 T3，3%）

### 一、任务目标

能熟练运用 Spring Initializr 创建项目，理解 pom.xml 依赖管理及起步依赖的作用；掌握 application.yml 配置文件编写，能够自定义配置并加载到 Bean 中。

### 二、涉及知识点

- Spring Initializr / IDEA New Project 创建 Spring Boot 项目
- 起步依赖（spring-boot-starter-web、-jdbc、-test 等）
- 多环境配置文件（application-dev.yml / application-prod.yml）
- `@ConfigurationProperties` 将配置绑定到 Bean
- Actuator 健康检查

### 三、任务要求

1. 使用 Spring Initializr（https://start.spring.io）创建 Spring Boot 2.7.x（或 3.x）项目，项目坐标为：
   - groupId：`com.cqvie.contest`
   - artifactId：`contest-registration-system`
   - 包名：`com.cqvie.contest`
2. 引入起步依赖：Web、Validation、DevTools、Lombok、MySQL Driver、MyBatis-Plus（选入）、Actuator。
3. 配置多环境：`application.yml`（公共）+ `application-dev.yml`（开发）+ `application-prod.yml`（生产）。
4. 自定义一个配置类 `ContestProperties`，使用 `@ConfigurationProperties(prefix = "contest")` 绑定配置项，包含：
   - `contest.name`：系统名称
   - `contest.version`：系统版本
   - `contest.max-registration-per-user`：单用户最大报名数
5. 编写一个 `HealthCheckController`，访问 `/api/info` 返回 `ContestProperties` 中的配置。
6. 配置 Actuator，暴露 `health`、`info` 端点。
7. 启动项目，通过浏览器访问 `http://localhost:8080/actuator/health` 返回 `UP`。

### 四、交付物

1. 完整的可启动项目（Git 仓库链接）。
2. 项目说明文档 `README.md`。
3. 启动截图（IDEA 控制台 + 浏览器访问 `/actuator/health` 与 `/api/info`）。

### 五、评分要点

| 评分项 | 分值 |
|---|---|
| 项目能用 `mvn spring-boot:run` 成功启动 | 20 |
| 依赖配置合理，pom.xml 规范 | 15 |
| 多环境配置文件完整可切换 | 20 |
| 自定义 `ContestProperties` 正确绑定 | 20 |
| Actuator 健康检查可访问 | 10 |
| README 文档完整 | 15 |

## 任务 B4：使用 MyBatis-Plus 实现学生 / 竞赛 / 报名模块的 CRUD（支撑 T4，7%）

### 一、任务目标

能够整合 MyBatis-Plus，编写 Mapper 接口实现对数据库的增删改查；掌握声明式事务管理，能使用 `@Transactional` 注解处理业务逻辑中的事务一致性问题。

### 二、涉及知识点

- MyBatis-Plus BaseMapper、IService 基础用法
- 实体类注解：`@TableName`、`@TableId`、`@TableField`
- 条件构造器（LambdaQueryWrapper）
- 分页插件（PaginationInnerInterceptor）
- `@Transactional` 事务注解
- 多表关联查询

### 三、任务要求

1. 在 MySQL 5.7 中创建数据库 `contest_registration`，建表：
   - `t_user`（用户表：id、username、password、role、create_time）
   - `t_contest`（竞赛表：id、name、level、start_time、end_time、status、create_by）
   - `t_registration`（报名表：id、user_id、contest_id、register_time、status、remark）
   - `t_score`（成绩表：id、registration_id、score、rank、award_level）
2. 编写实体类 + Mapper 接口 + Service 接口与实现。
3. 在 `UserService`、`ContestService`、`RegistrationService` 中分别实现：
   - 单体增、删、改、查
   - 分页查询
   - 条件查询（例如：查询某学生所有报名的竞赛）
4. 在 `RegistrationServiceImpl.register(userId, contestId)` 中使用 `@Transactional`，保证报名（`t_registration` 新增）+ 用户报名次数（`t_user.register_count`）更新的事务一致性；当报名次数超过配置上限时，抛出 `BizException` 使事务回滚。
5. 编写 JUnit 测试覆盖全部 Service 方法，通过率 100%。

### 四、交付物

1. SQL 建表脚本（`doc/schema.sql`）与测试数据脚本（`doc/data.sql`）。
2. 实体 / Mapper / Service / Controller 源码。
3. 单元测试代码及测试报告。
4. 任务报告（含多表关联查询 SQL 设计思路、事务实现说明）。

### 五、评分要点

| 评分项 | 分值 |
|---|---|
| 数据库建模合理，外键 / 索引设计合规 | 15 |
| MyBatis-Plus 实体与 Mapper 配置正确 | 15 |
| 三个模块 CRUD 功能完整 | 25 |
| 分页 + 条件查询实现正确 | 15 |
| `@Transactional` 事务一致性用例正确（含事务回滚验证） | 20 |
| 单元测试通过率 100% | 10 |

## 任务 B5：开发自定义"操作日志"Starter（支撑 T5，5%）

### 一、任务目标

能分析 `@SpringBootApplication` 注解结构，理解自动装配与条件注解的原理；理解 Spring Boot 的 Starter 机制设计思想，能解释其如何实现"开箱即用"。

### 二、涉及知识点

- `@EnableAutoConfiguration` 与 `AutoConfiguration.imports`
- `@Conditional`、`@ConditionalOnClass`、`@ConditionalOnProperty`
- `@ConfigurationProperties`
- 多 Module Maven 工程
- Starter 命名规范

### 三、任务要求

1. 新建 Maven 子模块 `contest-log-spring-boot-starter`，作为自定义 Starter。
2. 在 Starter 中提供：
   - `ContestLogProperties`：配置前缀 `contest.log`，包含 `enabled`、`save-to-db`、`async`、`max-content-length` 属性
   - `ContestLogService`：负责日志记录
   - `ContestLogAutoConfiguration`：使用 `@ConditionalOnProperty(prefix = "contest.log", name = "enabled", havingValue = "true", matchIfMissing = true)` 条件装配
   - `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 文件（Spring Boot 3.x）或 `META-INF/spring.factories`（Spring Boot 2.x）
3. 在主工程 `contest-registration-system` 中引入该 Starter，通过简单配置即"开箱即用"。
4. 编写测试用例验证：
   - `contest.log.enabled=false` 时，`ContestLogService` Bean 不被装配；
   - `contest.log.enabled=true` 时，Bean 正常工作。
5. 提交一份"自定义 Starter 设计与自动装配原理"报告（不少于 800 字），包含：
   - `@SpringBootApplication` 注解结构分析
   - 自动装配的加载流程
   - 自定义 Starter 与官方 Starter 的异同

### 四、交付物

1. `contest-log-spring-boot-starter` 模块源码。
2. 主工程使用该 Starter 的示例代码。
3. 单元测试。
4. 设计与原理分析报告。

### 五、评分要点

| 评分项 | 分值 |
|---|---|
| Starter 模块结构规范，符合命名约定 | 15 |
| `AutoConfiguration.imports` / `spring.factories` 配置正确 | 15 |
| 条件装配（`@ConditionalOnProperty` 等）使用正确 | 20 |
| 主工程"开箱即用"验证通过 | 15 |
| 单元测试覆盖装配开关场景 | 15 |

## 任务 B8：使用 AOP 与拦截器实现日志记录与登录校验（支撑 T8，6%）

### 一、任务目标

能运用 Spring AOP 技术实现系统日志记录、性能监控等功能，实现业务与非业务逻辑解耦；掌握拦截器（Interceptor）的配置与使用，实现用户登录校验与权限控制。

### 二、涉及知识点

- `@Aspect`、`@Pointcut`、`@Around`、`@Before`、`@AfterReturning`、`@AfterThrowing`
- JoinPoint、ProceedingJoinPoint、MethodSignature
- 自定义注解 + AOP
- `HandlerInterceptor`、`WebMvcConfigurer`
- 登录 Token / JWT 校验

### 三、任务要求

1. **AOP 日志切面**：
   - 定义自定义注解 `@OperLog`，属性包括 `value`（操作说明）、`module`（模块名）、`saveRequestData`（是否记录入参）。
   - 编写 `OperLogAspect`，通过 `@Around` 记录方法入参、出参、执行耗时、调用者 IP。
   - 日志异步写入 `t_oper_log` 表。
2. **AOP 性能监控切面**：
   - 对所有 Service 方法统计耗时；
   - 当耗时 > 500ms 时，使用 WARN 级别输出慢方法告警。
3. **拦截器登录校验**：
   - 实现 `LoginInterceptor`，拦截除 `/api/auth/login`、`/doc.html`、`/actuator/**` 外的所有请求；
   - 校验请求头 `Authorization: Bearer <token>`，解析 JWT 并放入 `ThreadLocal`；
   - Token 无效 / 过期返回统一 401 响应。
4. **权限注解**：
   - 定义 `@RequiresRole("ADMIN")` 注解，使用 AOP 校验当前用户角色；不匹配返回 403。
5. 编写单元测试覆盖：
   - `@OperLog` 成功记录日志；
   - 性能监控慢方法告警；
   - 未登录访问返回 401；
   - 无权限访问返回 403。

### 四、交付物

1. AOP 切面与拦截器源码。
2. 自定义注解 `@OperLog`、`@RequiresRole` 源码及使用示例。
3. `t_oper_log` 表数据截图（至少 20 条真实调用产生的日志）。
4. 单元测试代码与测试报告。

### 五、评分要点

| 评分项 | 分值 |
|---|---|
| `@OperLog` + AOP 日志切面实现正确 | 25 |
| 性能监控切面实现合理 | 15 |
| `LoginInterceptor` 配置与 JWT 校验正确 | 20 |
| `@RequiresRole` 权限注解 + AOP 实现 | 15 |
| `t_oper_log` 日志数据完整 | 10 |
| 单元测试覆盖全部场景 | 15 |
