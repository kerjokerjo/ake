# 小组每周 PPT 汇报考核实施细则（GP）

每个小组每周派 1 名成员上台汇报本周组内进展，全学期累计若干次。考核项编号 GP，占总成绩 4%，满分 100，**组内成员同分**。

一、组织方式

分组要求：每组不超过 4 人；建议组长 1 人、技术骨干 1~2 人。汇报频率：每周 1 次（按教学周）；汇报顺序：组内成员轮流，确保每人至少上台 1 次。每次汇报时长：5 分钟讲解 + 2 分钟答疑。

二、PPT 内容要求

每周 PPT 至少包含以下章节：

| 章节 | 内容要点 |
| --- | --- |
| 本周目标 | 计划完成的功能/任务清单 |
| 完成情况 | 实际完成的功能、关键截图、可演示成果 |
| 关键问题 | 本周遇到的技术难题与解决思路 |
| 任务分工 | 各成员承担的工作与完成度 |
| 下周计划 | 下一周任务分配与里程碑 |

三、评分维度（每周一次评分，学期累计取平均）

| 维度 | 权重 | 评分要点 |
| --- | --- | --- |
| PPT 质量 | 25% | 结构完整、排版规范、图文并茂 |
| 进度真实性 | 25% | 完成情况与代码仓库提交一致；演示真实可运行 |
| 汇报表达 | 20% | 主讲人逻辑清晰、术语规范、时间控制 |
| 团队协作 | 20% | 任务分工合理、组员配合得当、答疑互助 |
| 问题与改进 | 10% | 能识别问题并提出可执行的改进措施 |

四、5 档评分参考

| 分段 | 总体表现 |
| --- | --- |
| 90~100 | PPT 精美、进度真实、表达流畅，分工与协作典范，能主动提出改进 |
| 80~89 | PPT 完整、进度真实、表达清楚，分工合理 |
| 70~79 | PPT 基本完整，进度可信，但表达或分工存在小问题 |
| 60~69 | PPT 简陋或与代码不符，分工不均、协作一般 |
| <60 | 未上台、PPT 抄袭、进度造假或严重超时 |

五、最终得分计算

GP 最终分 = 学期内全部 GP 单次得分的算术平均；缺席一次按 0 分计入平均（教师可对个人请假情况单独备注，但小组分仍按整体表现计算）。

六、原始记录

每次汇报由任课教师当场记录得分与评语；PPT 文件按周归档，与课堂录像/照片共同保留 3 年。
