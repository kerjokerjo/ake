# 项目答辩考核实施方案

结果性评价 60%，由作品讲解（D1，30%）+ 技术问答（D2，30%）构成，覆盖 T3~T8 全部技术性课程目标。每位学生独立计分。

一、考核形式

依托小组作品（需求分析报告、源代码、录屏演示）开展答辩。每组答辩 30 分钟（讲解 15 分钟 + 问答 15 分钟）；地点：实训机房；评委组 3~4 人（课程负责人 1 + 任课教师 2 + 企业导师 1 可选）。每位学生须独立讲解本人负责的模块，独立回答评委追问。

二、答辩材料

学生提交以下材料作为答辩依据：

| 材料 | 来源 |
| --- | --- |
| 需求分析报告（终稿） | 小组（GR） |
| 完整源代码 | 小组（GC） |
| 作品录屏演示讲解 | 小组（GV） |
| 个人贡献说明 | 个人 |
| 答辩 PPT | 小组共用，按个人模块分页 |

三、D1 作品讲解评分（30%，满分 100）

每位学生须讲解本人负责模块，按以下 6 个维度独立评分：

| 维度 | 分值 | 评分要点 |
| --- | --- | --- |
| 项目搭建（T3） | 15 | 工程结构、配置、自动装配 |
| 持久层（T4） | 20 | MyBatis-Plus、事务、SQL 设计 |
| 自动装配（T5） | 15 | Starter 设计、`@Conditional` 应用 |
| 测试（T6） | 15 | 单元测试、覆盖率、接口测试 |
| RESTful（T7） | 15 | 接口规范、统一响应、文档 |
| AOP（T8） | 20 | 日志切面、拦截器、权限控制 |

四、D2 技术问答评分（30%，满分 100）

评委从以下题目方向中按学生讲解深度抽问 3~5 题，每位学生至少被问 1 题。每题按"完整 90~100 / 基本正确 75~89 / 部分正确 60~74 / 错误 <60"打分，最终按算术平均得到 D2 得分。

| 方向 | 题目示例 |
| --- | --- |
| T3 项目搭建 | `@SpringBootApplication` 组成？多环境配置如何切换？`@ConfigurationProperties` 与 `@Value` 区别？ |
| T4 持久层与事务 | 默认事务传播行为？事务失效的常见场景？MyBatis-Plus LambdaQueryWrapper 优势？ |
| T5 自动装配 | 自动装配加载流程？`@ConditionalOnProperty/Class` 场景？2.7+ 装配文件如何配置？ |
| T6 测试 | `@SpringBootTest` 与 `@WebMvcTest` 差异？MockMvc 如何断言 JSON？覆盖率工具？ |
| T7 RESTful | REST 规范要点？`@RestControllerAdvice` 用法？参数校验失败的状态码？ |
| T8 AOP | `@Around` vs `@Before`？AOP 自调用如何生效？拦截器与 AOP 差别？JWT 校验流程？ |

五、答辩流程

答辩前 1 周：学生提交全部材料；答辩前 1 天：评委抽签确定顺序与题目池；答辩当天：小组整体介绍（10 分钟）+ 成员讲解（15 分钟）+ 评委提问（15 分钟）+ 评分（5 分钟）；答辩后 3 天内：教师汇总成绩，提交教研室。

六、答辩纪律

全程录像，作为评价原始材料；学生着正装、礼貌作答；对成绩有异议可在 3 个工作日内复核；抄袭、代答本项记 0 分并上报学院。
