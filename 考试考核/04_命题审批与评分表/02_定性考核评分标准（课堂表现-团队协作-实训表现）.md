# 定性考核评分标准（课堂表现 / 团队协作 / 实训表现）

> 本表完整引用《课程目标达成度评价报告》表 9，结合 T1、T2、T9、T10 的考核要点具体化，供教师打分参考。
> 三个考核环节分别对应：课堂表现（A1~A4 主要依据）、团队协作（基于团队软件开发项目，支撑 B 类作业评分）、实训表现（含实操、规范、成果，支撑 B3~B8 评分）。

## 一、课堂表现

| 分值段 | 评分标准 |
|---|---|
| 90~100 | (1) 全程专注课堂，无迟到、早退、缺勤；<br>(2) 主动参与课堂提问、案例研讨，回答准确且能结合 Web 项目实战实操拓展；<br>(3) 积极配合互动，主动分享学习见解，带动课堂交流氛围 |
| 80~89 | (1) 课堂专注度高，偶有迟到且及时整改，无缺勤；<br>(2) 能主动参与互动，回答问题基本准确；<br>(3) 配合小组讨论并发表观点，按时完成课堂即时测试任务，质量达标 |
| 70~79 | (1) 课堂基本专注，1~2 次迟到 / 早退，无缺勤；<br>(2) 被动参与互动，点名能回应且答案无原则性错误；<br>(3) 参与小组讨论不敷衍，按时完成课堂即时测试任务，质量基本符合要求 |
| 60~69 | (1) 课堂注意力不集中，3 次及以内迟到 / 早退，无缺勤；<br>(2) 极少主动互动，点名回应答案存在部分偏差；<br>(3) 小组讨论参与度低，课堂即时测试任务完成延迟 |
| <60 | (1) 多次迟到、早退或缺勤；<br>(2) 课堂走神做与学习无关的事，拒不参与互动；<br>(3) 不配合小组讨论，未完成课堂即时测试任务，或完成质量极差且存在严重知识性错误 |

## 二、团队协作（基于团队软件开发项目）

| 分值段 | 评分标准 |
|---|---|
| 90~100 | (1) 主动承担核心测试任务（如测试方案设计、关键模块测试），责任心强；<br>(2) 精准对接成员工作，及时沟通进度、反馈问题，主动协调解决协作分歧；<br>(3) 带动团队高效完成任务，为团队核心贡献者，获全员认可 |
| 80~89 | (1) 主动接受分配任务，无推诿，责任心良好；<br>(2) 按时沟通工作进展，及时反馈测试问题，配合解决协作小分歧；<br>(3) 认真完成自身工作，对团队任务完成有重要贡献，获成员认可 |
| 70~79 | (1) 接受分配任务，基本履行职责，无重大失职；<br>(2) 配合团队沟通，经提醒可反馈工作情况，对协作分歧无过激行为，配合团队决议；<br>(3) 按时完成基础工作，对团队任务有一定贡献，无明显负面影响 |
| 60~69 | (1) 被动接受任务，存在轻微推诿，责任心一般；<br>(2) 团队沟通不积极，多次提醒才反馈进度，测试问题未及时同步，偶因自身沟通影响团队进度；<br>(3) 完成核心工作但有疏漏，需他人协助修正，贡献度较低 |
| <60 | (1) 不接受任务或擅自脱离团队工作，责任心缺失；<br>(2) 拒不参与团队沟通，隐瞒测试问题，引发团队重大分歧，严重影响协作氛围；<br>(3) 未完成分配任务，导致团队项目进度滞后、质量不达标 |

## 三、实训表现（含实操、规范、成果）

| 分值段 | 评分标准 |
|---|---|
| 90~100 | (1) 独立高效完成 Spring Boot 项目搭建、配置及功能开发，代码结构清晰，符合规范；<br>(2) 熟练运用自动装配、Starter 等核心机制，能独立解决复杂技术问题；<br>(3) 严格遵守编码规范，文档完整，主动总结技术心得 |
| 80~89 | (1) 独立完成项目核心功能开发，代码规范，偶有细微疏漏但可快速修正；<br>(2) 掌握核心配置与持久层技术，能解决常见开发问题；<br>(3) 遵守规范，文档齐全，提交实训心得 |
| 70~79 | (1) 在少量指导下完成项目开发，代码基本符合要求，存在 3~4 处疏漏但不影响整体运行；<br>(2) 能使用基本开发工具，可解决简单技术问题；<br>(3) 基本遵守规范，按时提交资料及心得 |
| 60~69 | (1) 需较多指导完成项目，代码有明显漏洞，修正后可运行；<br>(2) 测试工具使用不熟练，需他人协助；<br>(3) 轻微违规经提醒后整改，资料提交延迟或敷衍 |
| <60 | (1) 多次指导仍无法完成核心功能，代码无效；<br>(2) 无法使用基本开发工具，完全依赖他人；<br>(3) 多次违反规范拒不整改，资料严重缺失 |

## 四、与 T1/T2/T9/T10 的映射

| 考核项 | 课程目标 | 主要评分依据 |
|---|---|---|
| A1 网络法治意识评分 | T1 | 课堂表现 + 团队协作中体现的社会主义核心价值观与开源协作精神 |
| A2 严谨开发意识评分 | T2 | 课堂表现 + 实训表现中体现的工匠精神、代码规范遵守情况 |
| A3 开源社区使用能力评分 | T9 | 课堂表现中对 Spring 官方 Blog/GitHub 等开源社区动态的关注与讨论 |
| A4 英文文档阅读能力评分 | T10 | 课堂表现中展示的英文文档阅读与分享情况 |

## 五、评分建议

1. 教师每周至少对每位学生在以上三个环节进行 1 次打分；
2. 每月汇总一次；
3. 期末取学期内各次得分的算术平均值作为最终得分。
